Contract-review engine

  • Input: long-form agreement. Output: 500+ discrete obligations in a typed schema, reconciled against a standard template.

Lesson-planning AI — Brilla Public Charter Schools

  • Mode 1: unit overview + lesson number → complete, teach-ready lesson plan grounded in the network's curriculum and teaching expectations.
  • Mode 2: multi-turn coaching that walks a teacher through internalizing a plan before class.
  • Core requirement: quote accuracy at scale. Every passage a plan cites is extracted verbatim from the purchased book text, not recalled by the model.
  • Extraction is a five-strategy parser cascade with guards against the silent failure — a parse that succeeds and is wrong. Chapters carry source offsets, so every quotation is traceable to a position in the book.
  • In deployment. 900 lessons — 9 grade levels × 4 units × 25 lessons — are the current school year's K–8 reading curriculum, not a pilot corpus. All 900 human-reviewed and passed before entering classrooms.
  • Conditioned on grade level, not just grade band, so lessons are at-level: two grades inside one band reading the same text get different vocabulary load, scaffolding, and practice expectations.
  • Teacher adversarial review is the correction signal: reviewers attack each plan, and captured corrections improve the next generation run.
  • Per-mode model selection + prompt caching: ~$0.05 per generated plan; full-school usage projected at tens of dollars per month.

02 Research & projects

Autonomous MTG Arena agent

  • Harness for LLM-driven play of Magic: The Gathering Arena. The game has no API, so the bot drives the real client through its interface; the client publishes the legal move set, so the model only ever chooses among options it is already allowed to take.
  • Live result: a naive Haiku pilot with no game-specific tuning played 55 games against Arena's built-in AI and finished 27–28, a 49.1% win rate, at ~$0.03 per game — while the actuation layer still had known defects.
  • Loop: perceive (game log as truth, vision only for screen position) → decide (typed request to the model) → execute (verified clicks). Every reported success is provisional until the engine confirms it.
  • Runs on a fleet of VMware VMs with a health sensor that classifies nodes CRASH / WEDGE / ANOMALY / CRAWL / HEALTHY.
  • Engineering practice: log-first diagnosis over vision, per-mechanic eval gates, adversarial multi-agent code review.

04 Writing

Mostly one question: how do you know an AI system is actually working?

Teaching a language model to play Magic

A personal project, and the one where the ideas get tested at full depth. Four pieces, in reading order.

  • Building a bot that plays Magic: The Gathering Arena

    The game has no API, so the bot uses it the way a person does. How the game's own log made the vision layer almost disappear, and why a click that reports success usually didn't do anything.

  • An LLM refused to block 97% of the time

    A naive pilot reached 49% against Arena's own AI for three cents a game, then declined to block on 268 of 276 chances. It wasn't bad at combat — power and toughness appeared in zero of 4,201 prompts.

  • How do you put a number on a Magic position?

    A card's value can't be read off the card, every measurement of it is contaminated by the deck it came from, and what you condition on determines what the agent would learn to want. Some of the game can't be scored from a position at all.

  • Errors hiding in a 5.1M-game dataset

    A card that isn't a card, shipped with an 18-point win-rate outlier. 23 cards that were never once cast but kept turning up on the battlefield. And a join proved correct by arithmetic instead of inspection.

05 Methods

Deterministic rules / model judgment split

Rules that must be auditable become tested code. Only genuinely semantic work goes to a model. Cuts cost and error rate.

Evaluation as a build gate

Graded answer keys, regression runs, negative controls. A change that fixes one case and breaks another is visible before it ships.

Adversarial verification

Independent refute-by-default reviewers over every candidate finding. Perspective-diverse verifiers beat redundant ones.

Deliver into existing tools

Ship into what the user already opens. End-to-end scope: substrate, model layer, interface, adoption.
