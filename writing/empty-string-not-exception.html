An empty string is not an exception

Jack Wright · August 2026

A text extractor that returns "" on a scanned page has made a successful call. No exception fires. The row is silently empty. Nobody finds out until a downstream count looks slightly low — and "slightly low" is not a number anyone investigates.

I lost real content this way: an entire scanned attachment, and a schedule that existed in the source only as an image. Both were absent from the extracted corpus, and every stage of the pipeline reported success. Below are the four variants of this bug class I've now hit, and what each one actually needs. They share a shape: the output is empty-but-valid, or wrong-but-plausible, so the error path is unreachable by construction.

1. Empty-but-valid extraction

Any pipeline stage that can return an empty result on a legitimate input needs an explicit plausibility check. You cannot wait for an exception, because there is no error — a scanned page genuinely contains zero extractable characters.

The check that works: flag pages with low text volume and a large embedded image. That conjunction is the signature of a scan sitting in a text-native document, and it's cheap to compute at parse time. A page with no text and no image is plausibly blank; a page with no text and a full-page image is a page you are about to lose.

2. Unicode that renders identically and compares as different

Two strings that look the same on screen can score around 6% similar. The culprit is almost always PDF extraction artifacts: ligatures like ﬀ where you expect ff, or smart punctuation substituted for ASCII quotes and hyphens.

Normalize with NFKD before any text comparison, always, as the first thing that happens to a string. On one corpus this single fix moved 16 rows from "different" to "identical." Those 16 rows had been manufacturing findings — the system was confidently reporting divergences that did not exist, which is considerably worse than missing real ones. 

import unicodedata

def norm(s: str) -> str:
    return unicodedata.normalize("NFKD", s).casefold().strip()

3. "Absent" conflated with "I couldn't find it"

A locator that fails to find a clause and a document that genuinely lacks that clause must return different values. If both collapse to None, every downstream consumer treats a search failure as a substantive finding about the document.

Collapsing these cost me roughly 20 percentage points of accuracy and, worse, produced confident nonsense: assertions that an agreement omitted a protection it in fact contained, because the extractor had missed it. Return a three-state result — found, confirmed-absent, lookup-failed — and make downstream code handle the third explicitly.

4. Positional diffing across form families

Comparing two documents section-by-section is valid when they descend from the same template and meaningless when they don't. Two unrelated agreements will both have a clause numbered 1.1, and comparing them yields near-0% similarity for content that in substance overlaps heavily.

That output is a false comparison, not a finding. Cross-family comparison needs concept assignment — match on what the clause is, not where it sits. Positional methods should carry a guard that refuses to run when the two inputs aren't from the same family.

Two habits that catch the whole class

Count what should be conserved. Pages in, pages with text out. Obligations extracted, obligations matched. Any stage where a total can be compared against the stage before it will surface silent loss without you having to predict the mechanism.

Label a shortlist as a shortlist. Automated difference detection produces candidates for a human to examine. If the output isn't explicitly labeled that way, someone will treat it as ground truth — and in my experience the someone is me, three weeks later, having forgotten what the column meant.

The unifying rule: anywhere a stage can succeed while producing nothing, the plausibility check has to be written by hand. The exception handler you would otherwise rely on cannot fire, because from the program's point of view nothing went wrong.
