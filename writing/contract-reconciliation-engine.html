Contract obligation reconciliation engine

Status
Production
Role
Sole engineer
Stack
Python, LLM extraction + matching, pytest
Scale
500+ obligations per agreement

Problem

Executed commercial agreements must be checked against a standard obligation template. Review was manual. Reviewer availability bounded throughput, and omissions surfaced late in the contract lifecycle rather than at signature.

Interface

InputExecuted agreement. Long-form PDF, mixed text-native and scanned pages.
InputStandard template obligation set.
OutputCoverage matrix. Extracted obligation × template concept, with verdict per pair.
OutputGap routing. Each uncovered concept assigned to the responsible reader.

Pipeline

  1. Parse. PDF to text units. Scanned-page detection runs here; see failure modes below.
  2. Extract. Agreement text to typed obligation records. 500+ discrete obligations per agreement.
  3. Match. Semantic assignment of each extracted obligation to a template concept. Model-handled.
  4. Reconcile. Verdict per matched pair. Deterministic.
  5. Route. Each gap assigned to the reader who owns that concept.

Deterministic / model boundary

Stage 3 is the only stage with model authority. Stage 4 is code. The split is the load-bearing design decision: a reviewer disputing a verdict is directed to a named function with a test file, not to a prompt.

Decision classHandled by
Does obligation text X express template concept YModel
Numeric flooring — which side's figure governsCode
Window nesting — does a cure period fall inside a notice periodCode
Asymmetric verdicts — obligation binds one party onlyCode
Scope applicability — does the clause bind the reviewed entityCode

Rule count in code: approximately 150 tested functions. Model output is schema-validated at the tool-call layer, so a malformed response triggers a retry rather than entering the deterministic half.

Evaluation

Method: hand-graded case set constructed before the first production run. Negative controls included — items resembling gaps that are not gaps — to measure false-positive appetite rather than recall alone.

MetricValue
Gap recall92%
False positive rate0%

Failure modes found during build

Four defects in the parse and comparison stages, each silent — no exception raised, output plausible.

DefectEffectFix
Text extractor returns empty string on scanned page Successful call, empty row. One scanned attachment and one image-only schedule lost from the corpus. Flag pages with low text volume and large embedded image at parse time.
Unicode ligatures from PDF extraction Identically-rendered strings scored ~6% similar. Manufactured 16 false divergence findings. NFKD normalization before any text comparison.
"Absent" and "lookup failed" share a return value Extraction misses reported as substantive findings about the document. ~20 percentage points of accuracy. Three-state return: found / confirmed-absent / lookup-failed.
Positional diffing applied across form families Unrelated documents both number a clause 1.1. Near-0% similarity reported for heavily overlapping content. Concept assignment instead of position. Family guard on positional methods.

Measurement defect

A strictness rubric scored both sides of a comparison 5/5 and rendered the row clean while the penalty figure underneath had doubled. Root cause was upstream: the extraction schema had no numeric-value field, so no magnitude reached the rubric. The rubric could not be wrong because it could not see the deciding variable. Prompt-level fixes to the rubric would have had no effect.

Limitations

  • Requires a template. No unsupervised discovery of obligation types.
  • Match quality is bounded by extraction quality upstream.
  • Scale is hundreds of obligations per document, not millions.
  • Coverage matrix is a review artifact, not a verdict. Labeled as such in the output.
